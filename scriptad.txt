1. Contract giữa các Worker

Đây mới là phần tôi cho rằng quan trọng hơn bản thân tree.

Mỗi worker không giao tiếp với worker kế tiếp bằng kiểu:

Worker A → "một đống JSON" → Worker B

mà phải:

Worker A
   │
   ▼
OUTPUT ARTIFACT
   │
   ├── schema_version
   ├── artifact_id
   ├── campaign_id
   ├── parent_artifact_id
   ├── worker_version
   ├── input_hash
   ├── status
   ├── payload
   └── validation
             │
             ▼
       CONTRACT VALIDATOR
             │
       ┌─────┴─────┐
       │           │
     VALID       INVALID
       │           │
       ▼           ▼
 Worker B       STOP/REPAIR

Contract chuẩn

Worker	Input	Output	Contract bắt buộc

W01	Product input	PRODUCT_RECORD	Fact phải có evidence
W02	Product Record	PAIN_MAP	Pain phân biệt observed/inferred
W03	Product + Pain	IDEA_POOL	Không tạo unsupported claim
W04	Selected Idea	MASTER_SCRIPT	Claim phải reference allowed claim
W04.5	Master Script	VOICE_TRACK	Có duration thực tế
W04.6	Voice Track	AUDIO_TIMELINE	Timestamp thực tế
W05	Script + Audio	VISUAL_BIBLE	Core/Derived versioned
W06	Audio + Script + Bible	SHOT_PLAN	Tổng duration khớp audio
W07	Shot Plan	MOTION_PLAN	Dominant + secondary actions
W07.5	Motion Plan	FEASIBILITY_REPORT	Risk/capability measurable
W08	Motion Plan	MOTION_CONSTRAINTS	Structured, không chỉ text
W08.5	Constraints	PREFLIGHT_REPORT	Physics/risk check
W09	Motion + State	KEYFRAME_PLAN	State transition rõ
W09.5	Keyframes	CONTROL_SPEC	Reference/control inputs
W10	Control Spec	PICTURE_RENDER_SPEC	Renderable
W10.5	Render Spec	RESOURCE_DECISION	Budget đủ
W11	Render Spec	SHOT_IMAGE	Asset versioned
W11.5	Image	IMAGE_QA_REPORT	Evidence/risk, không overclaim
W12	Approved Image	VIDEO_RENDER_SPEC	Chỉ render approved asset
W13	Video Spec	SHOT_VIDEO	shot_id + iteration_id
W13.5	Shot Video	VIDEO_QA_REPORT	Heuristic/evidence
W14	All approved assets	DRAFT_AD	Timeline deterministic
Final Gate	Draft	FINAL_AD	Human approval

2. Một thay đổi rất quan trọng: Contract ≠ Prompt

Không nên gọi:

{
  "motion_contract": {
    "forbidden": [
      "second_ball",
      "paddle_morphing"
    ]
  }
}

rồi nghĩ Video AI sẽ thực thi nó.

Nên tách thành 3 tầng:

MOTION_INTENT
      │
      ▼
MOTION_CONSTRAINTS
      │
      ├── semantic constraints
      ├── object constraints
      ├── temporal constraints
      └── risk constraints
      │
      ▼
MODEL_CONTROL_SPEC
      │
      ├── prompt
      ├── reference image
      ├── mask
      ├── control input
      ├── camera path
      └── model-specific parameters

Sau đó:

MODEL OUTPUT
     │
     ▼
EVIDENCE / QA
     │
     ▼
HUMAN

Như vậy hệ thống không giả vờ rằng prompt có khả năng "enforce" vật lý.

3. Hai loại QA phải được phân biệt

Đây là điểm cần sửa mạnh so với kiến trúc cũ.

Deterministic QA

Có thể PASS/FAIL:

resolution
aspect_ratio
duration
file_integrity
audio_duration
OCR presence
required metadata
budget
schema
duplicate hash
shot_id
iteration_id

Probabilistic QA

Chỉ được:

RISK_LOW
RISK_MEDIUM
RISK_HIGH

hoặc:

{
  "identity_similarity": 0.87,
  "reference_similarity": 0.91,
  "motion_complexity": 0.74,
  "artifact_risk": 0.68
}

Không được biến những con số này thành sự thật tuyệt đối.

Ví dụ:

VIDEO QA

duration        PASS
resolution      PASS
OCR              PASS

identity_risk   HIGH
artifact_risk   MEDIUM
motion_risk     HIGH

              ↓

HUMAN GATE

Đây là kiến trúc thực tế hơn rất nhiều.

9. Resource/Budget Manager phải nằm ngang toàn hệ thống

Không nên chỉ có:

W10.5 Budget Gate

mà phải có:

RESOURCE MANAGER
                           │
       ┌───────────────────┼───────────────────┐
       │                   │                   │
     IMAGE               VIDEO               LLM
       │                   │                   │
   credits             credits             tokens
   retries             retries             requests
   concurrency         concurrency         rate-limit

Nó quyết định:

CAN_RUN(worker, shot)

trước mỗi expensive operation.

Ví dụ:

Budget còn:
Image = 20
Video = 7

Campaign cần:
Image = 8
Video = 8

→ Image: ALLOW
→ Video: BLOCK / RESERVE / FALLBACK

Đặc biệt phải reserve budget trước khi gọi API, không phải gọi xong mới tính.

# GRAMMAR → STRUCTURE → EVENT FILTER → CHARACTER → REACTION

## 1. MỤC TIÊU

Hệ thống không muốn dùng LLM để tự suy luận toàn bộ từ một bài báo.

Mục tiêu là biến câu tiếng Việt thành một cấu trúc ngữ pháp có thể mã hóa bằng số, để Python có thể xử lý cấu trúc đó một cách deterministic.

LLM chủ yếu làm nhiệm vụ:
TEXT → xác định cấu trúc ngữ pháp

Python làm nhiệm vụ:
GRAMMAR STRUCTURE → lọc → ánh xạ → xử lý logic

LLM cuối cùng, nếu cần, chỉ làm nhiệm vụ:
STRUCTURED DATA → câu văn tự nhiên.

---

## 2. KHÔNG XỬ LÝ TOÀN BỘ BÀI BÁO

Một bài báo có rất nhiều câu nhưng không phải câu nào cũng có giá trị đối với World Simulator.

Do đó hệ thống tạo một PHỄU:

NEWS
↓
SENTENCE
↓
GRAMMAR
↓
GRAMMAR CODE
↓
FILTER
↓
GIỮ / LOẠI
↓
EVENT / INFORMATION hữu ích
↓
CHARACTER
↓
REACTION

Những câu có cấu trúc không phục vụ hệ thống sẽ bị loại càng sớm càng tốt.

Ví dụ:

- câu chỉ mô tả thời gian → có thể bỏ
- câu chỉ mô tả địa điểm → có thể bỏ
- câu mang thông tin nền nhưng không tạo ra tác động → có thể bỏ
- câu chứa cấu trúc có khả năng tạo EVENT/CAUSE/RESULT/CLAIM... → giữ.

Việc lọc dựa trước hết vào cấu trúc, không dựa vào việc LLM tự viết lại ý nghĩa.

---

## 3. GRAMMAR ĐƯỢC MÃ HÓA

Mỗi đơn vị ngữ pháp có một mã số.

Ví dụ:

S → mã số
P → mã số
O → mã số
CAUSE → mã số

Một cấu trúc:

S + P + O + CAUSE

sẽ trở thành:

02-03-04-25

Chuỗi số này là GRAMMAR CODE.

Python không cần đọc lại câu tiếng Việt để biết cấu trúc.

Nó chỉ cần so khớp chuỗi số với các pattern đã được định nghĩa.

---

## 4. GRAMMAR CODE KHÔNG PHẢI VALUE

Đây là nguyên tắc quan trọng.

GRAMMAR CODE chỉ mô tả:

"Câu này được cấu tạo như thế nào?"

VALUE mô tả:

"Câu này nói về cái gì?"

Ví dụ:

02-03-04-25

có thể chứa:

02 = Công an
03 = xử phạt
04 = doanh nghiệp
25 = vi phạm quy định

Một câu khác có thể có cùng GRAMMAR CODE:

02 = Giám đốc
03 = thưởng
04 = nhân viên
25 = đạt doanh số

Hai câu có cùng cấu trúc nhưng VALUE khác nhau.

Vì vậy:

GRAMMAR ≠ EVENT.

GRAMMAR là cấu trúc để Python biết cách đọc và phân loại dữ liệu.

VALUE mới chứa nội dung thực tế.

---

## 5. TREE QUAN TRỌNG HƠN MỘT CHUỖI PHẲNG

Không nên chỉ biến toàn bộ câu thành một chuỗi duy nhất.

Câu phải được xem như một TREE.

Ví dụ:

CL
└── MC
    ├── S
    │   └── NP
    ├── P
    │   └── VP
    ├── O
    │   └── NP
    └── CAUSE
        └── SC

Mỗi node có mã số.

Do đó Python có thể nhìn cấu trúc ở nhiều độ sâu:

LEVEL cao:
CL

LEVEL tiếp theo:
MC / SC

LEVEL tiếp theo:
S / P / O / C / A

LEVEL tiếp theo:
NP / VP / PP...

LEVEL sâu hơn:
N / V / Adj / Adv...

Như vậy cùng một câu có thể được phân tích từ tổng quát đến chi tiết.

---

## 6. GRAMMAR CODE LÀ CÁCH NÉN CẤU TRÚC

Thay vì truyền cho Python:

"Chủ ngữ là cơ quan chức năng, vị ngữ là xử phạt, tân ngữ là doanh nghiệp..."

Python nhận:

02-03-04

và lấy VALUE tương ứng từ dữ liệu.

Điều này tạo ra một lớp trung gian:

TEXT
→ GRAMMAR TREE
→ NUMBER TREE
→ PYTHON

LLM không cần liên tục diễn giải bằng ngôn ngữ tự nhiên.

---

## 7. GRAMMAR LÀ PHỄU, KHÔNG PHẢI NỘI DUNG

Hệ thống không cố biến mọi cấu trúc ngữ pháp thành dữ liệu có giá trị.

Ngược lại:

GRAMMAR TREE
→ xác định nhánh nào đáng giữ
→ loại nhánh không cần thiết
→ giữ các nhánh có khả năng mang thông tin hữu ích.

Ví dụ các cấu trúc có thể dẫn đến:

EVENT
CAUSE
CONS
CLAIM
CONT
REL
PURP
COND
CONTR

có thể được giữ lại tùy mục đích của pipeline.

Các thành phần chỉ có vai trò phụ trợ nhưng không tạo giá trị cho hệ thống có thể bị bỏ ở tầng filter.

---

## 8. SAU KHI LỌC MỚI ĐẾN CHARACTER

Sau khi lọc được thông tin hữu ích:

GRAMMAR
+
VALUE
↓
EVENT / INFORMATION

Sau đó hệ thống mới đưa EVENT vào từng CHARACTER.

Mỗi CHARACTER có một bộ mã riêng mô tả đặc điểm của nhân vật.

Không cần mô tả tính cách bằng một đoạn văn dài.

Ví dụ về mặt nguyên lý:

CHARACTER
→ các trục tính cách
→ mỗi trục có mã số
→ toàn bộ tạo thành CHARACTER CODE.

Python có thể dùng CHARACTER CODE để quyết định cách nhân vật phản ứng trước cùng một EVENT.

---

## 9. REACTION KHÔNG PHẢI LÀ MỘT ĐOẠN VĂN CỐ ĐỊNH

Reaction nên được xem là OUTPUT của việc kết hợp:

EVENT / INFORMATION
+
CHARACTER
+
STATE / RELATION / CONTEXT
+
các quy tắc của hệ thống.

Grammar cung cấp cấu trúc để xác định và tổ chức thông tin đầu vào.

Không được mặc định rằng:

GRAMMAR CODE = REACTION CODE.

Cần kiểm nghiệm bằng dữ liệu thực tế xem Grammar đóng vai trò:

- chỉ là bộ phân tích cấu trúc;
- là một điều kiện lọc;
- hay có ảnh hưởng trực tiếp đến Reaction.

---

## 10. Ý TƯỞNG CỐT LÕI

Hệ thống đang cố chuyển một phần công việc mà LLM thường làm bằng token/ngôn ngữ tự nhiên thành xử lý cấu trúc.

Thay vì:

TEXT
→ LLM suy luận
→ LLM suy luận tiếp
→ LLM viết phản ứng
→ LLM viết câu

hệ thống hướng tới:

TEXT
→ GRAMMAR TREE
→ NUMBER TREE
→ FILTER
→ STRUCTURED EVENT
→ CHARACTER CODE
→ RULE / MAPPING
→ REACTION STRUCTURE
→ LLM biểu đạt thành câu nếu cần.

Python trở thành bộ máy xử lý cấu trúc.

LLM không bị loại bỏ hoàn toàn.

LLM được đẩy về đúng nơi nó có lợi thế:
- nhận diện ngôn ngữ;
- xử lý phần ngữ nghĩa khó;
- biểu đạt ngôn ngữ tự nhiên.

Python đảm nhiệm phần:
- mã hóa;
- so khớp;
- lọc;
- routing;
- lookup;
- áp dụng luật;
- quản lý dữ liệu;
- tạo cấu trúc deterministic.

---

## 11. NGUYÊN TẮC KIỂM CHỨNG

Không giả định trước rằng mọi thứ đều deterministic.

Mỗi tầng phải được kiểm chứng bằng dữ liệu.

Đặc biệt phải kiểm tra:

1. Các LLM có phân tích cùng một câu thành cùng cấu trúc hay không.
2. Các cấu trúc nào xuất hiện thường xuyên nhất.
3. Các cấu trúc nào thực sự hữu ích cho việc lọc news.
4. Cấu trúc nào dẫn tới EVENT.
5. Cấu trúc nào dẫn tới CAUSE / RESULT / CLAIM...
6. Cùng một EVENT nhưng khác cách diễn đạt có tạo ra các Grammar Code khác nhau hay không.
7. Nếu Grammar Code khác nhau nhưng EVENT giống nhau thì hệ thống có cần chuẩn hóa chúng về cùng một EVENT hay không.
8. Character Code kết hợp với EVENT như thế nào để tạo Reaction.
9. Phần nào có thể làm hoàn toàn bằng Python.
10. Phần nào bắt buộc phải để LLM xử lý.

Mục tiêu cuối cùng không phải là thay thế LLM bằng mọi giá.

Mục tiêu là tìm ra phần nào của quá trình có thể chuyển từ suy luận xác suất của LLM sang cấu trúc và luật deterministic mà không làm mất thông tin cần thiết.
